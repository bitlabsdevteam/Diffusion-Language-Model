## Architecture (notebook pipeline)

1. **Tokenizer**: byte-level BPE trained from scratch on TinyStories wrapped in a chat template (`<|user|>…<|assistant|>…<|end|>`). Special tokens include `[MASK]`, the diffusion noise token. Wrapped in `PreTrainedTokenizerFast`; `PAD_ID/MASK_ID/BOS_ID/EOS_ID` are module globals used throughout.
2. **Data**: `TokenBlockDataset` streams stories → chat format → concatenated token buffer → fixed `SEQ_LEN` blocks (no padding in practice; stories are packed across block boundaries).
3. **Model** (`DiffusionTransformerLM`): bidirectional `nn.TransformerEncoder` (pre-norm, GELU) with token + learned position + **timestep embedding** (`time_emb`, size `diffusion_steps+1`), tied input/output embeddings. No causal mask.
4. **Training objective** (`corrupt_with_mask`, `diffusion_loss`): sample `t ∈ [1,T]` per sequence, mask each non-special token with prob `t/T` (linear schedule), cross-entropy on masked positions only. Note this is an unweighted loss (no `1/t` reweighting as in LLaDA's ELBO).
5. **Sampling** (`diffusion_generate`): prompt tokens fixed, response region starts fully `[MASK]`; for `s = T..1` predict all positions, fill masked ones with sampled tokens, then **re-mask the lowest-confidence** generated tokens according to a decreasing mask ratio (confidence-based remasking, as in LLaDA). Returns per-step frames.
6. **Visualization**: Pillow/imageio render the recorded frames as a terminal-style GIF (two renderers: plain and a "neon" one in cell 23).

Training uses HF `accelerate` (bf16 if supported), AdamW + cosine warmup, grad accumulation, saves only the final checkpoint to `checkpoints/final/{model.pt,config.json,tokenizer/}`.

## Gotchas

- The training data is only TinyStories, so the model produces story-like text regardless of prompt.
- Sequence length is capped by `cfg.seq_len` (learned position embeddings); `diffusion_generate` clamps `prompt + max_new_tokens` to it.

## Cosine-schedule clone (`Final_Diffusion_LLM_from_scratch_TinyStories_Inference_Fixed_Cosine.ipynb`)

- Clone of the Fixed notebook (left untouched) with the linear masking / unmasking schedule replaced by the MaskGIT/MD4 cosine `p(u) = sin(pi*u/2)`. Research notes, formulas and sources: `COSINE_SCHEDULE_RESEARCH.md` (+ section "5b" in the notebook).
- The schedule enters four places: forward corruption (`mask_prob` in the model cell), the ELBO weight (`elbo_weight`, exact discrete `T*(p_t - p_{t-1})/p_t`, MDLM Eq. 8; linear keeps the old `1/ratio` expression so `linear/linear/STRATIFIED_T=False` is bit-identical to the Fixed notebook), the sampler (`_n_masked_after`: `ceil(L*p((s-1)/N))` per block; steps that reveal nothing skip the model call), and the optional time input (`_time_index` maps through `p^-1` when sampling and training schedules differ).
- Config cell: `NOISE_SCHEDULE` (training) and `SAMPLING_SCHEDULE` (sampling) are independent, both `"cosine"`; `STRATIFIED_T=True`; `EVAL_REFERENCE_SCHEDULE="linear"`; `RUN_NAME="cosine"` (separate checkpoint folder). `DiffusionLMConfig.noise_schedule` defaults to `"linear"` so old checkpoints load.
- Gotcha: the reported `val` / `train(eval)` are the **linear-schedule** ELBO (comparable with the Fixed notebook and `hyper_trials.jsonl`); the loss under the cosine training schedule is logged separately as `val (own)` / `val_loss_own`. Only the continuous-time ELBO is schedule-invariant; at T=128 the two discrete bounds differ slightly.
- Gotcha: the two "cosines" in the literature are mirror images (MaskGIT/MD4 `sin(pi*u/2)`, mean mask rate 0.64, used here; MDLM code `1 - cos(pi*u/2)`, mean 0.36). Results for one do not transfer to the other. Cosine is not expected to lower the val bound (schedule invariance, higher estimator variance, hence stratified `t`) and does not fix the token-frequency plateau; the expected gain is sample quality per sampling step (evidence in MD4 is on images). Recommended Colab ablation: 2x2 of training x sampling schedule, with block decoding on and off.
- Tests: `python test_cosine_notebook.py` (70 checks, needs torch/transformers/tokenizers/accelerate/matplotlib; runs the real cells on CPU with a synthetic corpus): schedule math, `E[w*p] = 1`, stub-model Monte Carlo `E[loss] = ln V` for both schedules, mean mask rate 2/pi vs 0.5, stratified-t marginal, bit-identical regression to the Fixed notebook, sampler counts / skipped calls / block schedules / time index, config compatibility. The older training / resume / grid / quit suites (99 + 29 checks, session scratchpad, not in the project) also pass against the clone. Not run on Colab or TinyStories.
